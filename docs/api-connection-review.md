# API 연결 검토

2026-10-01 한국 시간의 초기 실패와 후속 실제 응답을 구분해 기록합니다. 최신 조사에서는 법령·행정규칙·자치법규의 실제 목록과 전문 응답 형식을 확인하고 연동 코드의 문제를 수정했습니다. 운영 백엔드 배포와 원문 저장·전수 수집은 계속 대기 상태입니다. 공개 Vercel 페이지는 별도의 고정 시연이며 실시간 법령 API를 호출하지 않습니다.

## 실제 응답에 맞춘 연동 수정

법령 전문 8개 조문을 실제로 읽은 뒤, 행정규칙과 자치법규의 응답을 기존 코드가 처리하지 못하는 문제를 확인했습니다.

- 행정규칙은 `AdmRulService`의 바로 아래 `행정규칙기본정보`에 식별자·발령일·시행일을 제공합니다. 이 경로를 읽고 반복된 `조문내용`을 원래 순서로 모두 보존합니다. 관련 규정이나 부칙의 식별자·날짜를 대신 사용하지 않습니다.
- 자치법규 버전 조회는 `MST=자치법규일련번호`이고, 안정 식별자 조회는 `ID=자치법규ID`입니다. 기존 버전 번호를 `ID`로 보내던 요청을 수정했습니다. 근거는 [공식 자치법규 본문 API 안내](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=ordinInfoGuide)이며 이 안내는 실제 HTTPS 200으로 확인했습니다.
- 자치법규의 실제 `LawService`·`자치법규기본정보`·`조문/조` 형식을 지원합니다. `조문여부=N`인 장·절 제목은 조문에서 제외하고, 빈 응답과 다른 자료·버전의 응답은 계속 거부합니다.
- 법령 응답의 복합 `법령키`를 버전 일련번호로 간주하지 않습니다. 응답에 버전 식별자가 없으면 전문을 읽었더라도 버전 검증은 미확인으로 유지합니다.

수정 후 백엔드 단위·통합 테스트 **168개**가 통과했습니다. 테스트는 명시적으로 합성 응답을 사용하며 공식 연결 성공을 대신하지 않습니다. 실제 소량 조회 결과는 아래 기록과 JSON 증거를 따릅니다.

## 실데이터 화면으로 전환하는 순서

현재 공식 법령 저장소는 SQLite 색인과 원문 파일로 이미 구현되어 있어 PostgreSQL 전환이 연결 문제 해결의 선행 조건은 아닙니다. 서버 준비 후 같은 OC로 소량 조회를 확인하고, 원문 저장·검색·재시작 후 유지 여부를 확인합니다. 접근 가능한 HTTPS 백엔드 주소와 운영 인증을 Vercel 서버 환경에 등록한 뒤 `VITE_PUBLIC_PREVIEW=false`로 재배포해 실제 로그인/API 화면으로 전환합니다. 자세한 값과 확인 항목은 [운영 연결 안내](deployment.md)를 따릅니다.

현재 운영 백엔드 구축 대기 지시를 유지하며, 이 코드 수정으로 서버를 시작하거나 전체 법령을 수집하지 않았습니다. 샘플 전문 조회 성공은 전수 수집이나 모든 법령의 법적 적용성 확인을 뜻하지 않습니다.

## 검토에서 보완한 문제

- 프록시의 접속 거부를 일반 네트워크 오류로만 표시하던 부분을 구분합니다. 프록시 403은 재시도 대상에서 제외하고 수집 상태를 접근 차단으로 남깁니다.
- 번호가 붙은 장·절 제목을 실제 조문으로 읽지 않도록 합니다. 기본정보의 법령명·공포·시행 정보를 본문·부칙의 다른 정보와 섞지 않습니다.
- 조문에 직접 붙은 호 아래 목의 내용을 보존하고, 요청 버전이 특정되지 않은 ID 조회는 해당 버전을 확인했다고 표시하지 않습니다.
- 변경될 수 있는 ID만으로 기존 전문을 계속 재사용하지 않도록 하고, 삭제된 조문을 유효한 인용 근거로 사용하지 않도록 검사합니다.
- 원본 파일이 없거나 SHA-256이 일치하지 않는 자료를 인용·입안 모델 근거에서 제외하고 사유를 표시합니다. 목적 검색에서도 삭제 조문을 제외하며, 일반적인 삭제 절차를 규정한 조문은 유지합니다. 법령 인용 조회는 먼저 색인으로 후보 법령을 찾아 전체 법령의 모든 버전을 정렬하지 않도록 보완합니다.
- HTTP 200으로 반환된 오류·로그인·잘못된 검색 응답을 조회 성공으로 표시하지 않고, 검색 응답에 포함된 OC와 링크 인증값을 제거합니다.
- 개발 실행은 비공개 `.env`를 불러오며, 다른 환경에서 없는 `/workspace` 경로를 기본 캐시로 사용하지 않습니다. 운영 인증 설정은 개발 프런트엔드로 우회하지 않습니다.
- 패키지 다운로드도 HTTP 상태와 로그인 만료를 확인한 뒤 ZIP을 내려받도록 보완합니다.

각 수집·파싱 회귀 검증은 명시적으로 합성 응답과 임시 저장소를 사용합니다. 이를 공식 제공자 연결이나 실제 법령 정확성의 증거로 간주하지 않습니다. 과거 전체 연혁, 별표·별지 파일, 법률 해석과 기관 적용성은 이번 연결 확인으로 해결되지 않습니다.

세 자료의 실제 표본 형식과 식별자는 후속 조회에서 확인했지만 모든 응답 변형·현행/시행예정·연혁 조회 조건은 검증되지 않았습니다. 새 목록에 시행예정 버전만 나타나는 경우, 보관된 이전 버전의 계속 적용 여부를 현재 구현이 확정하지 못하고 기준일 근거를 확인 불가로 반환할 수 있습니다. 실제 응답과 버전 범위를 추가로 확인해야 합니다.

## 실행한 검증과 증거

백엔드 전체 단위·통합 테스트 **157개**가 통과했습니다. 로그인 활성화 프런트엔드 빌드와 실제 임시 HTTPS 브라우저 검증도 통과했습니다. 후자는 로그인·실제 MCP·모바일 화면과 함께 7개 문서 및 manifest가 든 ZIP 8개 항목의 내용을 확인했습니다. 다운로드 전 세션을 만료시키면 HTTP 401 뒤 로그인 화면으로 돌아가며 오류 응답을 파일로 저장하지 않았습니다. 합성 테스트에는 비공개 OC를 불러오지 않았습니다.

[공개 검증 기록](api-connection-evidence.json)에 공식 API 실패, 내부 API·MCP 결과, 임시 HTTPS 브라우저 결과와 테스트 범위를 저장했습니다. 이 검증에서는 백엔드 서버 설치·공개 배포·전국 수집을 실행하지 않았습니다.

## 백엔드 연결 확인 순서

[배포 안내](deployment.md)에 따라 도구·저장소·비공개 환경·영구 저장 위치를 준비합니다. 현재 클라우드의 `.env`는 Git에서 제외되어 다른 서버의 Git 복제본으로 자동 전달되지 않으므로 해당 서버에 별도로 등록합니다.

먼저 저장소 루트에서 다음 명령으로 공식 API 소량 조회를 확인합니다.

```bash
uv run --env-file .env --project backend --frozen python scripts/check-law-api.py
```

`provider_access_verified: true`와 종료 코드 0을 확인한 뒤 백엔드를 시작하고 인증된 API·MCP를 확인합니다. 소량 조회 성공도 전국 수집 완료나 전체 법적 적용성 검증을 뜻하지 않습니다. 실제 전체 수집과 Vercel의 공개 HTTPS 연결은 이 확인 후 진행합니다.
