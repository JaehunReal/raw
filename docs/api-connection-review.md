# Mac mini 준비 전 API 연결 검토

2026-10-01 한국 시간 기준으로, 사용자가 제공한 OC를 비공개 `.env`에서 불러와 실제 국가법령정보 API에 요청했습니다. **현재 공식 서버 응답을 받지 못했으며, 계정 승인·유효성과 실제 원문 수신은 미확인입니다.** 백엔드는 집의 Mac mini 준비를 기다리고 있으며 Render 서비스와 공개 웹 배포는 진행하지 않습니다.

## 실제 연결 확인 결과

법령 `target=law`, 행정규칙 `target=admrul`, 자치법규 `target=ordin` 목록을 자료별 1건만 요청했습니다. 세 요청 모두 실행 환경의 HTTPS 프록시가 403으로 차단했습니다. 원문 저장소에 수집 자료를 추가하거나 전체 수집 작업을 시작하지 않았습니다.

| 확인 대상 | 결과 |
| --- | --- |
| 비공개 OC 로드 | 성공, 값은 응답·기록에서 제외 |
| 공식 법령·행정규칙·자치법규 | `proxy_access_denied`, 403, 공식 응답 미수신 |
| 인증된 웹 법령 설정 조회 | HTTP 200, `configured: true`, 누락 설정 없음 |
| 원격 법령 검색 REST | HTTP 503, `ProxyError` |
| 로컬 규정 그래프 | HTTP 200, 시연 12개 문서·31개 관계 |
| 실제 MCP 도구 탐색 | HTTP 200, stdio 도구 4개 |
| 실제 MCP 조문 관계 조회 | HTTP 200, 대상과 상위법을 포함한 3개 노드 |
| 미인증 API 접근 | HTTP 401 |
| 공식 원문 수집 | 0건, 미완료, 전체 수집 작업 없음 |

웹 API 확인은 운영 인증을 적용한 임시 저장소와 ASGI 테스트 클라이언트에서 수행했습니다. MCP는 실제 자식 프로세스와 공식 SDK를 사용했으며 결과를 모의 응답으로 대체하지 않았습니다. 이 결과는 Mac mini 설치나 공개 웹 배포, 국가법령정보 서버 연결 성공을 뜻하지 않습니다. 기존 Markdown 규정집도 변경하지 않았습니다.

## 검토에서 보완한 문제

- 프록시의 접속 거부를 일반 네트워크 오류로만 표시하던 부분을 구분합니다. 프록시 403은 재시도 대상에서 제외하고 수집 상태를 접근 차단으로 남깁니다.
- 번호가 붙은 장·절 제목을 실제 조문으로 읽지 않도록 합니다. 기본정보의 법령명·공포·시행 정보를 본문·부칙의 다른 정보와 섞지 않습니다.
- 조문에 직접 붙은 호 아래 목의 내용을 보존하고, 요청 버전이 특정되지 않은 ID 조회는 해당 버전을 확인했다고 표시하지 않습니다.
- 변경될 수 있는 ID만으로 기존 전문을 계속 재사용하지 않도록 하고, 삭제된 조문을 유효한 인용 근거로 사용하지 않도록 검사합니다.
- 원본 파일이 없거나 SHA-256이 일치하지 않는 자료를 인용·입안 모델 근거에서 제외하고 사유를 표시합니다. 목적 검색에서도 삭제 조문을 제외하며, 일반적인 삭제 절차를 규정한 조문은 유지합니다. 법령 인용 조회는 먼저 색인으로 후보 법령을 찾아 전체 법령의 모든 버전을 정렬하지 않도록 보완합니다.
- HTTP 200으로 반환된 오류·로그인·잘못된 검색 응답을 조회 성공으로 표시하지 않고, 검색 응답에 포함된 OC와 링크 인증값을 제거합니다.
- 개발 실행은 비공개 `.env`를 불러오며, Mac에서 없는 `/workspace` 경로를 기본 캐시로 사용하지 않습니다. 운영 인증 설정은 개발 프런트엔드로 우회하지 않습니다.
- 패키지 다운로드도 HTTP 상태와 로그인 만료를 확인한 뒤 ZIP을 내려받도록 보완합니다.

각 수집·파싱 회귀 검증은 명시적으로 합성 응답과 임시 저장소를 사용합니다. 이를 공식 제공자 연결이나 실제 법령 정확성의 증거로 간주하지 않습니다. 과거 전체 연혁, 별표·별지 파일, 법률 해석과 기관 적용성은 이번 연결 확인으로 해결되지 않습니다.

실제 제공자의 세 자료 형식과 식별자·현행/시행예정 조회 조건도 아직 검증되지 않았습니다. 새 목록에 시행예정 버전만 나타나는 경우, 보관된 이전 버전의 계속 적용 여부를 현재 구현이 확정하지 못하고 기준일 근거를 확인 불가로 반환할 수 있습니다. 실제 응답과 버전 범위를 확인한 뒤 검증해야 합니다.

## 실행한 검증과 증거

백엔드 전체 단위·통합 테스트 **157개**가 통과했습니다. 로그인 활성화 프런트엔드 빌드와 실제 임시 HTTPS 브라우저 검증도 통과했습니다. 후자는 로그인·실제 MCP·모바일 화면과 함께 7개 문서 및 manifest가 든 ZIP 8개 항목의 내용을 확인했습니다. 다운로드 전 세션을 만료시키면 HTTP 401 뒤 로그인 화면으로 돌아가며 오류 응답을 파일로 저장하지 않았습니다. 합성 테스트에는 비공개 OC를 불러오지 않았습니다.

[공개 검증 기록](api-connection-evidence.json)에 공식 API 실패, 내부 API·MCP 결과, 임시 HTTPS 브라우저 결과와 테스트 범위를 저장했습니다. Mac mini에서의 실행·공개 배포·전국 수집은 미실행입니다.

## 집에서 확인할 순서

[Mac mini 준비 안내](macmini-setup.md)에 따라 도구·저장소·비공개 환경·영구 저장 위치를 준비합니다. 현재 클라우드의 `.env`는 Git에서 제외되어 Mac mini의 Git 복제본으로 자동 전달되지 않으므로 해당 Mac에 별도로 등록합니다.

먼저 저장소 루트에서 다음 명령으로 공식 API 소량 조회를 확인합니다.

```bash
uv run --env-file .env --project backend --frozen python scripts/check-law-api.py
```

`provider_access_verified: true`와 종료 코드 0을 확인한 뒤 백엔드를 시작하고 인증된 API·MCP를 확인합니다. 소량 조회 성공도 전국 수집 완료나 전체 법적 적용성 검증을 뜻하지 않습니다. 실제 전체 수집과 Vercel의 공개 HTTPS 연결은 이 확인 후 진행합니다.
