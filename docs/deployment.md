# Mac mini 백엔드 준비 후 Vercel 연결

프런트엔드는 Vercel, Python API는 사용자의 Mac mini 서버에서 운영할 예정입니다. **현재 백엔드 구축과 공개 배포는 보류 중이며, 발급·검증한 공개 웹 주소는 없습니다.** Mac mini 서버가 준비되면 운영 방식과 외부 접근 경로를 결정하고 실제 연결을 확인한 뒤 Vercel을 연결합니다.

집에서의 설치·비공개 설정·로컬 API와 실제 MCP 확인은 [Mac mini 실행 안내](macmini-setup.md)를 따릅니다. 공개 연결을 만들기 전에 공식 API 소량 조회도 별도로 확인할 수 있습니다.

## 현재 준비된 범위

Vercel의 `/api` 함수는 로그인 세션을 확인하고 Python 백엔드에 요청을 전달하도록 구현되어 있습니다. 로그인·규정 조회·편집·문서 다운로드와 실제 MCP 호출의 운영 경로는 로컬에서 검증했습니다. 이 결과가 Mac mini나 Vercel의 공개 배포 성공을 의미하지는 않습니다.

Python 3.12 이상과 `uv`로 Mac mini에서 API를 직접 실행하는 방식과 Docker 컨테이너 방식 중 하나를 나중에 선택할 수 있습니다. 이식 가능한 `Dockerfile`, `.dockerignore`, `scripts/production-entrypoint.py`는 유지합니다. Docker 이미지 다운로드와 컨테이너 기동은 이 클라우드 환경에서 검증하지 못했으며, Mac mini의 운영체제·아키텍처에서도 별도 확인이 필요합니다. 이번 변경에서는 서버를 설치하거나 실행하지 않습니다.

## Mac mini에서 준비할 항목

SQLite 색인·공식 원문·수집 체크포인트, 편집 규정집, 생성 패키지가 서버 재시작 후에도 남도록 저장 위치와 백업을 정해야 합니다. Docker 구성의 기본 저장 경로는 `/var/data`이며, Mac mini에서 직접 실행하는 안내는 사용자 폴더의 `Library/Application Support/RuleCraft`를 사용합니다. 실제 Mac에서 저장·백업·복구를 확인해야 합니다. API는 한 프로세스에서 수집 작업과 MCP 자식 프로세스를 운영합니다. 재시작으로 중단된 수집은 사용자가 다시 시작하고, 저장된 버전과 체크포인트를 재사용합니다.

공식 법령 수집에 필요한 `RULECRAFT_LAW_OC`는 **Mac mini의 백엔드 프로세스 환경**에 등록합니다. Vercel이나 브라우저에는 등록하지 않습니다. 계정 승인과 Mac mini에서 공식 API에 실제로 접근 가능한지는 별도 확인해야 합니다. 현재 확인한 공식 원문 수집 건수는 0건입니다. [공식 수집 설정과 범위](official-laws.md)를 참고하세요.

백엔드의 `RULECRAFT_API_TOKEN`도 Mac mini의 서버 환경에 보관합니다. Vercel 프록시가 사용하는 같은 이름의 서버 환경 변수에는 동일한 토큰을 등록합니다. 토큰은 브라우저에 전달하지 않으며, `VITE_` 변수·저장소·로그에 넣지 않습니다.

## Vercel이 연결할 주소

외부에서 실행되는 Vercel 함수는 Mac mini의 `localhost`, `127.0.0.1` 또는 공유기 내부의 사설 IP에 직접 연결할 수 없습니다. Mac mini를 준비할 때 외부에서 접근 가능한 **실제 HTTPS 원점 주소**를 확보해야 합니다. 터널, 리버스 프록시 또는 다른 네트워크 구성을 사용할지는 그때 결정합니다. 아직 도메인이나 호스트 이름을 정하거나 발급하지 않았습니다.

Vercel의 GitHub 프로젝트를 사용할 때는 저장소 **JaehunReal/raw**의 루트(`.`)를 Root Directory로 설정합니다. 루트의 `vercel.json`이 설치·빌드 명령과 `frontend/dist` 출력을 지정하고, 로그인/API 함수도 함께 포함합니다. 이 프로젝트 연결과 실제 배포는 백엔드 주소 준비 후 진행합니다.

| Vercel 서버 환경 변수 | 준비 후 등록할 값 |
| --- | --- |
| `RULECRAFT_BACKEND_URL` | Mac mini 백엔드에 연결되는 실제 HTTPS 원점 주소. 경로·쿼리는 제외합니다. |
| `RULECRAFT_API_TOKEN` | Mac mini 백엔드의 같은 이름 변수와 동일한 토큰 |
| `RULECRAFT_WEB_PASSWORD` | 워크스페이스용 강한 임의 비밀번호 |

비밀번호와 토큰에 `VITE_` 접두사를 붙이지 않습니다. 브라우저 번들에는 이 값이 들어가지 않고, 공개 기능 플래그 `VITE_REQUIRE_LOGIN=true`만 사용합니다. 설정이 없거나 백엔드가 중단되면 연결 오류를 표시하며 시연 응답으로 대체하지 않습니다.

## 서버 준비 후 확인할 동작

실제 HTTPS 백엔드의 health 응답과 미인증 API 차단을 확인한 뒤 Vercel 로그인, 규정 조회·편집, 패키지 다운로드, 실제 MCP 호출을 확인합니다. Mac mini 재시작 후 편집 내용과 패키지가 유지되는지도 확인해야 합니다. 공식 법령 수집은 계정 설정 뒤 실제 요청·진행·오류·수집 수량으로 검증합니다.

최신 [API 연결·로컬 실행 증거](api-connection-evidence.json)는 임시 HTTPS 게이트웨이와 운영 API를 사용한 로그인·규정 12개 조회·실제 MCP 조회·공식 전문 0건 상태·ZIP 내용 검증·세션 만료 검증입니다. 백엔드 157개 테스트와 로그인 활성화 빌드가 통과했고, 모바일 390px 화면을 확인했습니다. 이 증거는 Mac mini 실행, 공급자 배포 또는 공개 URL 검증을 대신하지 않습니다. [이전 배포 검증 기록](deployment-evidence.json)도 보관합니다.

## 운영 범위

로그인은 한 워크스페이스의 공유 비밀번호 방식입니다. 세션은 HttpOnly·Secure·SameSite=Strict 쿠키로 12시간 유지되고 비밀번호를 바꾸면 기존 세션은 무효가 됩니다. 사용자별 계정·역할·감사 로그와 로그인 시도 제한은 별도 확장 사항입니다. 백엔드 API 토큰과 브라우저의 외부 인증 헤더를 사용자 응답에 노출하지 않습니다.

Vercel 프록시는 업로드를 4MB 이하로 제한하고 백엔드 응답을 최대 45초 기다립니다. 법령 수집은 Mac mini 백엔드에서 비동기로 계속 실행하도록 구성되어 있습니다. 큰 Vision 이미지·대용량 본문·ZIP 다운로드에는 별도 전송 경로가 필요할 수 있습니다.

단일 프로세스·단일 저장소 구성은 대규모 공동 편집이나 수평 확장을 제공하지 않습니다. 공식 법령 수집과 인용 존재 확인도 모든 법령의 적용성·실질적 적법성 검토를 대신하지 않습니다.
