# Vercel에서 실제 웹 앱 사용하기

프런트엔드는 Vercel, Python API는 Render의 상시 실행 서버와 영구 디스크에 배포합니다. Vercel의 `/api` 함수가 로그인 세션을 확인하고 백엔드에 요청을 전달하므로 브라우저는 같은 웹 주소에서 규정 조회·편집·패키지 다운로드와 실제 MCP 예제를 사용합니다.

배포 설정을 작성하고 로컬에서 운영 경로를 검증하는 것과 공개 배포는 별개입니다. 이 작업 환경에는 Vercel·Render 계정 인증이 없으며 두 공급자 API 접속도 프록시 403으로 차단되었습니다. **현재 발급·검증한 공개 웹 주소는 없습니다.** 아래 계정 화면에서 저장소를 연결하거나, 클라우드 환경에 공급자 인증과 API 접근을 설정해야 실제 배포를 진행할 수 있습니다.

## 1. 영구 백엔드 만들기

[Render에서 이 저장소의 Blueprint 열기](https://render.com/deploy?repo=https://github.com/JaehunReal/raw)

`render.yaml`은 **유료 Starter 서버 1개와 유료 20GB 디스크**를 지정합니다. 생성 전에 Render 화면의 실제 요금을 확인하세요. 파일을 GitHub에 저장하는 것만으로 서비스가 생성되거나 과금되지 않습니다. Docker를 실행할 수 있는 기존 서버에 동일한 컨테이너와 영구 볼륨을 사용해도 됩니다.

배포가 끝나면 Render가 발급한 실제 HTTPS 주소와 생성된 `RULECRAFT_API_TOKEN`을 확인합니다. 토큰은 다음 Vercel 설정에 같은 값으로 넣습니다. 백엔드 주소의 `/api/health`는 정상 상태를 반환하고, 인증 없이 `/api/overview`를 직접 요청하면 401이어야 합니다.

`RULECRAFT_LAW_OC`는 기본 빈 값입니다. 웹과 로컬 시연 규정·MCP는 실행되지만 공식 원문 수집에는 승인된 국가법령정보 API 계정을 Render 환경 변수로 따로 등록해야 합니다. 현재 공식 원문 수집 건수는 0건이며, 배포가 이 요건을 대신하지 않습니다.

[백엔드 저장 경로·재시작·백업·한계](render-backend.md)를 확인하세요. 법령 원문과 편집 규정, 패키지는 `/var/data`에 남습니다. 서버 재시작으로 중단된 수집은 사용자가 다시 시작해야 하며, 저장된 버전과 체크포인트를 재사용합니다.

## 2. Vercel에 GitHub 저장소 연결하기

[Vercel의 새 프로젝트 화면 열기](https://vercel.com/new)

GitHub의 **JaehunReal/raw**를 가져오고 **Root Directory를 저장소 루트(`.`)** 로 둡니다. `frontend`를 루트로 지정하면 로그인/API 함수가 배포에 포함되지 않습니다. Framework Preset은 **Other**이며 루트의 `vercel.json`이 설치·빌드 명령과 `frontend/dist` 출력을 설정합니다. Node.js는 24.x입니다.

다음 세 변수를 Vercel의 서버 환경에 등록한 뒤 배포합니다. Preview와 Production에서 각각 사용할 수 있도록 범위를 설정합니다.

| Vercel 변수 | 입력할 값 |
| --- | --- |
| `RULECRAFT_BACKEND_URL` | Render에서 실제 발급받은 HTTPS 원점 주소. 경로·쿼리는 넣지 않습니다. |
| `RULECRAFT_API_TOKEN` | Render의 같은 이름 변수와 동일한 토큰 |
| `RULECRAFT_WEB_PASSWORD` | 워크스페이스용 강한 임의 비밀번호. 32자 이상의 무작위 값을 권장합니다. |

비밀번호와 토큰에 `VITE_` 접두사를 붙이지 마세요. 브라우저 번들에는 이 값이 들어가지 않습니다. 빌드는 공개 기능 플래그 `VITE_REQUIRE_LOGIN=true`만 사용합니다. 환경 변수를 바꾼 뒤에는 Vercel에서 재배포합니다.

완료 화면에서 **실제로 발급된 `*.vercel.app` 주소**를 열고 워크스페이스 비밀번호로 로그인합니다. 설정이 빠졌거나 백엔드가 중단되면 연결 오류를 표시하며, 성공한 것처럼 시연 JSON으로 대체하지 않습니다.

## 3. 배포 후 실제 확인

1. 로그아웃 상태의 `/api/overview` 요청이 401인지 확인합니다.
2. 로그인 후 시연 규정 12개와 관계 31개를 확인합니다. 기존 영구 규정을 수정했다면 수치는 달라질 수 있습니다.
3. **MCP 도구 → 조문 관계 탐색 → 실제 MCP 실행**에서 대상 조문과 상위법 2개의 결과를 확인합니다. 이 호출은 Render에서 실제 stdio MCP 작업 프로세스를 실행합니다.
4. **공식 법령**에서 수집 설정과 실제 원문 수량을 확인합니다. 계정 등록 전 0건·설정 필요가 정상이며, 계정을 등록한 뒤 실제 수집 요청·진행·오류를 확인해야 합니다.
5. 시험용 규정을 편집하고 패키지를 만든 뒤 백엔드를 재시작하여 편집 내용과 다운로드가 유지되는지 확인합니다.

로컬 검증 명령은 다음과 같습니다. 브라우저 검증은 Python Playwright, Chromium, OpenSSL이 설치된 환경에서 실행합니다.

```bash
VITE_REQUIRE_LOGIN=true npm run build --prefix frontend
npm run test:proxy
uv run --project backend python -m unittest discover -s tests -q
python tests/browser_deployment_smoke.py
```

브라우저 검증은 임시 HTTPS 프록시와 운영 인증 API, 복사한 시연 규정집을 사용해 실제 로그인·법령 상태·MCP·로그아웃을 확인합니다. 테스트 인증서는 임시로 생성하며 Vercel/Render에 설치하지 않습니다. 이 검증은 공급자 배포와 공개 주소 검증을 대신하지 않습니다.

이번 검증에서는 로그인 후 규정 12개, 실제 MCP 조회 3개, 공식 전문 0건·미완료, 로그아웃 후 401을 확인했습니다. 모바일 390px 화면에 가로 넘침과 브라우저 실행 오류가 없었습니다. 백엔드 117개·프록시 17개 테스트와 로그인 활성화 빌드가 통과했습니다. [실행 증거](deployment-evidence.json)에 공개 배포·컨테이너 빌드는 미검증 상태임을 함께 기록했습니다.

## 운영 범위

로그인은 한 워크스페이스의 공유 비밀번호 방식입니다. 세션은 HttpOnly·Secure·SameSite=Strict 쿠키로 12시간 유지되고, 비밀번호를 바꾸면 기존 세션은 무효가 됩니다. 사용자별 계정·역할·감사 로그와 로그인 시도 제한은 별도 확장 사항입니다. 백엔드 API 토큰은 브라우저에 전달하지 않으며, 쿠키·외부 인증 헤더를 백엔드로 전달하지 않습니다. 변경 요청은 같은 HTTPS 원점에서만 허용합니다.

Vercel 요청에는 본문 크기와 실행 시간 제한이 있습니다. 이 프록시는 업로드를 4MB 이하로 제한하고, 백엔드 응답을 최대 45초 기다립니다. 실제 수집은 백엔드에서 비동기로 계속 실행하므로 이 시간 제한에 걸리지 않습니다. 큰 Vision 이미지·대용량 법령 본문·ZIP 다운로드는 별도 전송 경로나 전용 서버가 필요할 수 있습니다.

SQLite와 작업 상태를 운영하는 백엔드는 한 프로세스·한 디스크 구성입니다. 대규모 공동 편집, 수평 확장, 모든 법령의 법적 적용성 검증이 구현되었다는 뜻은 아닙니다. [공식 수집 범위](official-laws.md)를 함께 확인하세요.
