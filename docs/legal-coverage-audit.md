# 법령 반영 범위 점검

점검일: 2026-09-30 · 대상: RuleCraft 현재 구현 (`37dd4ab`)

이 문서는 공식 수집기 구현 전 위 커밋의 점검 기록이다. 이후 추가한 수집·조회·입안 연동과 실제 환경의 수집 차단 상태는 [공식 법령 수집 안내](official-laws.md)에서 확인한다.

## 결론

현재 구현은 ‘적용되는 모든 법령을 반영하는 규정 제·개정 시스템’ 요구를 충족하지 못한다. MCP 통신, 로컬 Markdown 관계 탐색, Git 변경 영향 분석과 검토 문서 생성은 구현되어 있지만, 공식 법령을 수집하여 최신 상태로 유지하거나 법적 적합성을 검증하는 기능은 없다.

첨부 설계 문서는 기관별 법령·조례·지침·서식, 상위법 위임 한계 진단, 개정 전파와 교차 검증을 목표로 제시한다. 이는 검토 대상 요구사항이며 현재 구현의 검증 결과가 아니다. ‘전국 법령 전체 수집’과 ‘대상 기관·업무에 적용되는 법령 전체 반영’ 중 필요한 범위, 대상 기관, 업무 분야와 적용 기준일은 추가로 정해야 한다. 한국행정연구원은 현재 예제 기관일 뿐 확정된 운영 대상이 아니다.

## 실행 확인

기본 `GraphStore`를 실제 로드한 결과 문서 12개, 관계 31개, 구조 오류 0개였다. 문서 12개 모두 `status: demo`, `demo: true`였다. 공식 법령 및 모델 설정 값은 출력하지 않고 필요한 환경 변수의 존재와 어댑터 상태만 확인했다.

저장소 밖 임시 디렉터리에서 만든 합성 상위법·하위규정으로 다음 사례를 실행했다. 실제 법령에 대한 법률 해석 결과가 아니라 검사 범위의 한계를 보여 주는 사례다.

저장소의 고정된 Python 환경으로 `backend/.venv/bin/python /tmp/rulecraft-legal-audit.py`를 실행했다. [입력과 실제 결과 JSON](legal-coverage-evidence.json)에 합성 문서와 검사 결과를 보존했다. 아래 다섯 사례 모두 `valid: true`, `status: draft`, 산출물 7개, `legal_authority_verified: false`였다.

| 합성 사례 | 현재 처리 |
| --- | --- |
| 상위 문서는 특정 행위를 금지하고 하위 문서는 같은 행위를 허용 | 구조 검증 통과, 검토 문서 생성 |
| 하위 문서에서 `delegated_by`를 모두 제거 | 구조 검증 통과, 검토 문서 생성 |
| 존재하는 제15조에 존재하지 않는 제999항을 인용 | 구조 검증 통과, 검토 문서 생성 |
| 따옴표 없는 ‘…에 관한 법률 제999조’ 인용 | 해당 형태를 텍스트 인용 검사에서 놓쳐 구조 검증 통과 |
| 상위법에 없는 예외 신설 권한이 위임되었다고 하위 문서에서 주장 | 구조 검증 통과, 검토 문서 생성 |

폐지 상태, 미래 시행일과 유효하지 않은 개정일을 넣은 합성 문서도 시간에 관한 오류를 내지 않았다. 기존 규정집을 수정하지 않고 수행했다.

대조 사례인 `「상위법」 제999조`는 `unverified_text_citation` 오류로 탐지됐다. 반면 유효한 일반 텍스트 인용 `「상위법」 제15조에 따른다`는 위키링크나 관계 메타데이터가 없으면 역참조 그래프에 들어가지 않았다. 따라서 현재 영향 분석은 인용된 모든 규정의 전수 분석으로 해석할 수 없다.

## 구현 우선순위와 완료 기준

1. **수집 범위와 원문을 확정한다.** 대상에 따라 헌법·법률·시행령·시행규칙, 관련 행정규칙·고시, 자치법규, 기관 규정과 부칙·별표·별지를 목록화한다. 판례·해석례가 필요한 분야는 별도 근거 유형으로 관리한다. 공식 목록의 대상 건수와 실제 수집 건수, 실패·누락 목록을 대조해야 한다. ‘관련 없음’ 판정에도 근거와 검토자가 필요하다.
2. **공식 수집·동기화를 구현한다.** 공식 API의 실제 제공 범위와 접근 권한을 확인한 뒤 전체 페이지와 전문을 수집하고 조·항·호·목으로 분해한다. 법령 식별자, 공식 원문 주소, 공포·시행 정보, 수집 시각과 원문 해시를 보존한다. 초기 전수 수집과 후속 변경 동기화를 구분하고, 원문 변경은 Git 영향 분석으로 연결한다. 실패·누락을 정상 완료로 처리하지 않는다.
3. **시점과 근거 검색을 구현한다.** 공포일과 시행일을 구분하고 폐지·미래 시행·경과조치를 포함하여 적용 기준일의 버전을 선택한다. 연혁을 덮어쓰지 않는다. 기관·업무·지역에 따른 적용성 후보를 검색하고 사람이 확정한 적용 법령 목록과 비교한다. 입안 모델에 관련 원문과 조문 식별자를 제공하고 각 제안의 근거를 보존한다.
4. **법적 검토 항목을 구현한다.** 인용의 조·항·호·목과 적용 시점을 검증하고, 상하위 위임 근거·의무/금지 충돌·정의·절차·부칙을 검토한다. 확정할 수 없는 항목은 ‘검토 필요’로 남기고 최종 확정 단계에 진입하지 못하게 한다. 기관별 협의·예고·심사 절차도 근거에 따라 결정해야 한다. Git 병합은 법적 공포·시행의 증거가 아니다.
5. **화면과 승인 상태를 분리한다.** 시연 데이터, 구조 검사 통과, 원문 최신성, 적용 법령 수집 범위와 법제 검토 완료를 각각 표시한다. 확인되지 않은 자료를 ‘시행 중’으로 표시하지 않는다. 초안 다운로드와 최종 확정을 구분한다.

완료 검증에는 공식 목록 대조, 수집 실패 재시도, 개정·폐지·미래 시행의 기준일 선택, 항·호 인용, 위임 누락·충돌, 적용 법령 누락과 기관별 절차 사례가 필요하다. 수집 범위와 동기화 시점은 측정할 수 있지만 ‘모든 법률 해석이 항상 정확하다’는 보장으로 바꾸어서는 안 된다. 시스템이 확인한 근거·누락·판단 불가 항목과 담당자의 검토 결과가 함께 남아야 한다.
