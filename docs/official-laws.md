# 공식 법령 수집과 사용

공식 원문을 시연 규정집과 분리하여 보관한다. 웹의 **공식 법령** 메뉴에서 목록 전체와 전문의 수집 현황, 검색 결과와 원문 출처를 확인할 수 있다. 국가법령정보 공동활용 API의 법령·행정규칙·자치법규 목록을 대상으로 한다. 완료 상태는 선택한 API 목록의 이번 수집 범위에 대한 결과이며, 모든 법률 해석이나 기관에 적용되는 법령을 확정했다는 의미가 아니다.

## API 이용 신청

[국가법령정보 공동활용 서비스](https://open.law.go.kr/)에서 이용 신청한다. 현재 프로젝트의 운영 백엔드는 준비 단계이며 Render 서비스 생성과 전수 수집은 진행하지 않는다.

1. 공식 사이트에서 회원가입과 로그인 또는 신청 화면의 이용자 등록 절차를 진행한다. 등록한 이메일을 확인할 수 있어야 한다.
2. 공동활용 서비스 신청 화면에서 **Open API** 방식을 선택한다. 메뉴명은 사이트의 현재 안내를 따른다.
3. 이용자·연락처, 서비스명과 이용 목적을 입력하고, 제공 범위에서 **법령·행정규칙·자치법규의 목록과 본문** 이용을 신청한다. 별도 선택 항목이 없으면 이용 목적에 필요한 범위를 적는다.
4. 신청 완료 화면과 이메일에서 승인 또는 이용 가능 상태, 호출 조건과 `OC` 사용 안내를 확인한다. 처리 기간과 승인 조건을 임의로 확정하지 않는다. 서버 주소가 필수라면 아직 미정인 공개 주소를 만들어 적지 말고 구축 예정 서비스의 신청 방법을 공식 안내에 따라 확인한다.
5. 이용 가능한 계정의 실제 `OC` 식별값을 확인한 뒤 백엔드 환경 변수 `RULECRAFT_LAW_OC`에 등록한다.

신청 목적 예시:

> RuleCraft 규정 관리 서비스에서 법령·행정규칙·자치법규의 목록과 본문을 수집·검색하고, 기관 규정 제·개정 초안의 근거 확인 및 변경 영향 검토에 활용합니다.

`OC`는 법령 API의 이용자 식별 파라미터로, 통상 등록 이메일의 `@` 앞 ID를 사용한다. 예를 들어 `example@example.com`이면 `example`이다. 실제 신청 계정의 가이드와 승인 안내를 우선하여 값을 확인한다. 공공데이터포털의 일반 `serviceKey`를 그대로 사용하는 방식과 혼동하지 않는다.

2026-10-01 확인 시 이 클라우드 환경의 공식 신청 사이트·API 가이드 접속은 프록시 `403 Forbidden`으로 차단됐다. 따라서 위 절차의 최신 화면 이름과 신청 조건을 실시간으로 확인한 것은 아니다. 공식 사이트에서 현재 안내를 확인해야 하며, 계정 신청·승인이나 실제 원문 수집을 완료했다고 표시하지 않는다.

## 실제 수집에 필요한 설정

- `RULECRAFT_LAW_OC`: 국가법령정보 공동활용 서비스의 이용 신청 계정에 맞는 `OC` 식별값. 백엔드 환경 설정에 입력하며 저장소·브라우저·로그에 기록하지 않는다.
- HTTPS 접속 허용: `www.law.go.kr`, `open.law.go.kr`. 기본 API 주소는 `https://www.law.go.kr/DRF`다. 설정 안내는 [국가법령정보 공동활용 서비스](https://open.law.go.kr/)에서 확인한다.
- 선택 설정 `RULECRAFT_LAW_DIR`: 수집 원문과 SQLite 색인을 저장할 디렉터리. 기본값은 저장소의 `.rulecraft/national-law`이며 Git에 포함하지 않는다.

현재 개발 환경의 최초 확인 결과는 공식 사이트 프록시 접속 `403 Forbidden`, 식별값 미설정이었다. 따라서 구현의 합성 응답 테스트와 실제 공식 원문 수집 결과는 구분해야 한다. 테스트 자료를 공식 데이터로 주입하지 않는다. 실제 환경 설정을 적용한 뒤 수집 결과를 다시 확인해야 한다.

이후 사용자가 제공한 OC를 비공개 `.env`에 저장하고 로드를 확인했다. 2026-10-01에는 이 값을 사용해 법령·행정규칙·자치법규의 실제 목록 조회를 요청했으나 세 범위 모두 클라우드 프록시 403으로 차단됐다. 공식 응답을 받지 못해 계정 승인·유효성과 실제 제공자 형식은 확인하지 못했다. 수집 원문은 여전히 0건이다. [현재 연결 검토](api-connection-review.md)를 참고한다.

같은 날 14:33 한국 시간, 새 환경 설정의 OC로 다시 확인했을 때 법령 목록은 표본 1건과 목록 총수 5,621건의 실제 응답을 받았다. 표본 전문은 HTTP 403, 행정규칙·자치법규 목록은 HTTP 502로 실패했다. 모든 범위의 전문 검증과 전수 수집은 미완료이며 원문 저장은 하지 않았다.

저장소 루트에서 다음 명령으로 연결부터 확인한다. 목록 페이지와 본문을 자료별 최대 1건씩 요청하며 원문 저장소를 변경하지 않는다.

```bash
uv run --env-file .env --project backend --frozen python scripts/check-law-api.py
```

종료 코드 0과 `provider_access_verified: true`는 선택한 자료 범위의 소량 조회 성공이다. 종료 코드 2이면 `sources`의 오류를 확인한다. `proxy_access_denied`는 실행 환경 프록시 차단이며 OC 승인 여부를 확정하지 않는다. `--output .rulecraft/law-api-check.json`으로 인증값과 본문을 제외한 결과를 저장할 수 있다.

## 실행

웹의 **공식 법령**에서 수집 종류를 선택하고 수집을 시작한다. 페이지를 이동해도 백엔드 수집은 계속되며, 수집 현황에서 취소할 수 있다. 서버가 종료되면 진행 중 작업은 중단되므로 다음 실행에서 다시 수집한다.

실제 수집을 진행할 때는 저장소 루트에서 명령으로 실행할 수도 있다. 비공개 `.env`를 쓰지 않고 프로세스 환경에 설정한 경우에는 `--env-file .env`를 생략한다.

```bash
uv run --env-file .env --project backend --frozen python -m rulecraft.law_sync
```

전체 목록을 처음 페이지부터 확인하고 각 목록 항목의 전문을 받는다. 재실행은 공식 버전 식별자가 같은 원문을 재사용하며 실패한 전문을 다시 수집한다. 변경 가능한 ID만 있고 버전 식별자가 없는 항목은 매번 전문을 확인한다. 같은 버전의 원문도 다시 대조하려면 `--reset`을 사용한다. 수집 실패 시 명령의 종료 상태와 종류별 오류를 확인한다. 초기 전수 수집은 법령 수와 공식 서비스 요청 제한에 따라 오래 걸릴 수 있다.

## 보관과 완료 판정

원문 응답, 공식 식별자와 버전, 공포·시행 정보, 수집 시각, 출처 주소와 SHA-256을 보존한다. 개정된 버전은 기존 원문을 덮어쓰지 않는다. 전국 원문을 기존 Markdown 그래프에 한 번에 펼치지 않고 별도 색인으로 검색하여 필요한 조문을 읽는다.

공식 목록의 총수, 페이지별 식별자와 성공적으로 저장한 전문 수를 대조한다. 반복 페이지, 중복 식별자, 전체 개수 변동, 전문 식별자 불일치, 오류 응답 또는 저장 실패가 있으면 완료로 표시하지 않는다. 수집 현황의 `complete`와 함께 `scope`, 종류별 수량과 `limitations`를 확인해야 한다.

최신 수집 실행의 추가·변경·목록 제외 이력은 전체 기록을 페이지별로 조회한다. 상태 응답의 변경 미리보기만으로 모든 변경을 표시했다고 간주하지 않는다. ‘목록 제외’는 이번 응답에서 빠졌다는 의미이며 폐지를 자동 확정하지 않는다. 기관 규정에 선언한 관계와 일반 인용을 따라 직접·간접 영향 후보를 표시하며, 누락된 인용이나 적용성까지 자동 확정하지 않는다.

## 조회와 입안 반영

법령명·본문을 검색하고 기준일을 지정해 저장된 원문을 조회한다. 기관 규정 입안 시 선언한 상위법·본문 인용과 개정 목적에서 공식 근거를 검색하여 모델 입력과 검토 보고서에 원문 발췌, 버전, 출처와 해시를 함께 남긴다. 조·항·호 인용은 확보한 구조화 원문으로 확인하며 원문이나 구조가 없으면 확인 불가로 남긴다. 시연 문서가 공식 원문으로 승격되지는 않는다.

MCP의 `query_markdown_graph`도 `source_scope: "official"`로 저장된 공식 조문을 조회할 수 있다.

```json
{
  "agency_name": "국가법령",
  "rule_name": "수집한 공식 법령의 명칭",
  "article_no": "제7조의2",
  "source_scope": "official",
  "as_of": "2026-09-30"
}
```

공식 조회는 원문의 존재와 출처를 반환한다. 로컬 관계 조회는 기본값 `source_scope: "local"`을 사용한다. 수집하지 않은 원문은 생성해서 대신하지 않는다.

## 남는 범위

공식 서비스 실제 응답의 제공 범위와 접근 권한은 실행 환경에서 검증해야 한다. 전체 과거 연혁, 원문 응답 밖의 별표·별지 첨부파일, 조약·판례·해석례는 현재 목록 수집만으로 완전하지 않다. 기준일 조회도 저장한 버전과 시행 정보에 한정되며, 경과조치나 특례의 적용성을 자동 확정하지 않는다.

적용 법령 전수 목록, 상하위 위임의 범위, 조문 내용의 충돌, 기관별 협의·예고·심사와 최종 공포·시행 여부는 별도 검토가 필요하다. `verification.valid`는 구조 검사이고 `legal_authority_verified`는 여전히 `false`다. 근거 제공과 법적 적합성 승인을 구분한다.
