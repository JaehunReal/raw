## 1. 프로젝트 개요

### 1.1 배경 및 현장 병목점
공공기관 및 행정기관에서 지침·조례·사규 등 내부 규정을 제정하거나 개정할 때 실무 담당자는 다음과 같은 구조적 한계와 비효율에 직면합니다.

* **복잡한 행정 절차와 제출 서식의 파편화**: 입안, 부서 협의, 입법예고, 규제심사, 법제심사, 공포 등 단계별 필수 절차 파악 및 관련 공문서 세트(이유서, 신구조문대비표, 부칙 등) 수기 작성에 따른 과다 행정력 소모.
* **상위법 위임 한계 일탈 및 다단계 인용 누락**: 상위법령(법률-시행령-시행규칙) 개정 시 하위 지침 반영이 지연되거나, 조문 이동(Re-numbering) 시 타 조문·별표·서식에서 기존 조항을 잘못 인용하는 오류 다수 발생.
* **복잡한 전용 Graph DB 구축의 현실적 한계**: 대규모 엔터프라이즈 그래프 DB(Neo4j 등)는 공공기관 폐쇄망/망분리 환경에서 도입 단가가 높고 운영 유지보수가 까다로워 파일 단위로 관리되는 행정 현장과 괴리 발생.
* **지속적 개정 이력(Living Document) 추적의 어려움**: 규정은 한 번 만들어지고 끝나는 것이 아니라 주기적으로 개정되는데, 기존 RAG나 DB는 "어느 조문이 언제 바뀌어서 어떤 하위 규정에 영향을 미쳤는지"를 형상관리(Version Control)하기 어려움.

### 1.2 시스템 목표
1. **마크다운 기반 경량 지식그래프(Markdown-native LKG) 구축**: 별도의 무거운 DB 없이도 기관별 법령·조례·지침·서식을 마크다운(`.md`) 파일 계열(YAML Frontmatter + Wiki-Link)로 구조화하여 상위법-하위규정 간의 관계망을 직관적으로 시각화하고 탐색.
2. **GitOps 기반 변경 파급도(Delta Impact) 실시간 추적**: 규정 추가·개정 시 Git Diff(커밋/변경분)를 추적하여, 상위 조문 변경이 하위 지침과 서식에 미치는 영향을 역링크(Backlink) 그래프로 전수 자동 탐지.
3. **원스톱 지능형 행정 패키징**: 제·개정 목적 입력만으로 조문 초안, 3단 신구조문대비표, 제·개정이유서, 부칙(경과조치), 별표 서식 정비안까지 원클릭 생성.
4. **MCP(Model Context Protocol) 기반 공공 개방형 표준화**: 모델-도구-지식 간 연결을 MCP 표준 인터페이스로 추상화하여 온프레미스 sLLM, 망분리 환경, 타 공공기관으로의 자유로운 이식성 보장.

## 2. 심사 기준 대응 전략 (배점 100점)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        심사 지표 종합 대응 체계                         │
├────────────────────┬────────────────────┬──────────────────────────────┤
│    활용성 (40점)    │    완성도 (30점)    │      확산 용이성 (30점)       │
├────────────────────┼────────────────────┼──────────────────────────────┤
│• 올인원 문서 패키징 │• Git Diff 변경 추적│• .md 파일 기반 오픈 지식그래프│
│• 기관별 커스텀 룰셋 │• Re-numbering 검증 │• 표준 MCP 프로토콜 채택       │
│• 절차형 위저드 UI   │• 멀티 에이전트 교차│• LLaVA/Lev 오픈소스 스택     │
│• 시각적 관계도 뷰어 │• 허위 인용 0% 보장 │• 망분리/온프레미스 최적화    │
└────────────────────┴────────────────────┴──────────────────────────────┘
```

### 2.1 활용성 (40점) : 행정 실정 밀착 및 공통 활용성
* **올인원 공문서 세트 동시 산출**: 조문 초안뿐만 아니라 행정안전부/법제처 표준 3단 신구조문대비표(현행-개정안-개정이유), 입법예고문, 부칙(시행일·경과조치·타규정개정), 별지 서식 개정안을 완결된 문서 형태로 자동 생성.
* **기관별 맞춤형 디렉토리 및 템플릿 엔진**: 기관별(중앙부처, 지자체, 공기업 등) 규정 체계를 마크다운 폴더 트리로 모듈화하여 기관별 환경 설정 즉시 적용 가능.
* **절차 중심 대화형 위저드(Wizard) UX**: 제정/일부개정/전면개정 여부에 따라 다음 행정 절차와 필요 서식을 단계별로 시각화 안내.
* **인터랙티브 관계도 뷰어**: 특정 조문을 클릭하면 연결된 상위법, 하위 지침, 서식, 변경 이력이 노드 그래프와 타임라인으로 직관적 표출.

### 2.2 완성도 (30점) : 기능 완성도, 안정적 구동 및 사용 편의성
* **GitOps 기반 변경 영향도 역추적(Backlink Impact Traversing)**: 상위 법령이나 본칙 조항이 개정되어 마크다운 내용이 변경(Diff)되면, 해당 조문을 `[[인용]]`하거나 위임받은 모든 하위 `.md` 문서를 역링크 그래프 탐색으로 빠짐없이 전수 추출.
* **조 번호 이동(Re-numbering) 충돌 방지 엔진**: 조문 신설/삭제에 따른 번호 밀림 현상 발생 시, 해당 번호를 가리키던 모든 인용 관계(`cites: [[...]]`)를 탐지하여 자동 수정안 제안.
* **다단계 에이전트 교차 검증 (Zero-Hallucination Gate)**: 작성 에이전트와 검증 에이전트 간 분업을 통해 허위 조문 생성 및 법령 위재(존재하지 않는 조항 인용)를 100% 원천 차단.

### 2.3 확산 용이성 (30점) : 모델 비종속성 및 정보화 사업 이관 용이성
* **마크다운 기반 지식 자산화 (No-Vendor Lock-in)**: 고가의 전용 DB 없이도 표준 텍스트 형식인 마크다운(`.md`) 파일들로 지식그래프를 구축하므로, 어떤 공공기관이든 Git 레포지토리 복사만으로 즉시 적용 가능.
* **표준 Model Context Protocol (MCP) 전면 채택**: 모델과 내부 규정 DB/지식그래프/도구 간 통신을 MCP로 표준화하여 GPT-4o, Claude 등 상용 API뿐 아니라 온프레미스 오픈소스 sLLM(Solar, Llama 3 등)으로 모델 자유 교체 가능.
* **경량 오픈소스 스택(LLaVA, Lev, SQLite/Kùzu) 내재화**: 고비용 인프라 없이도 스캔본 서식 분석(LLaVA), 조문 파싱(Lev), 마크다운 링크 파서 연동 가능.
* **모듈형 마이크로서비스(MSA) 설계**: 공공기관 내부 규정관리시스템, 온나라 전자결재 등 정식 정보화 사업 개발·운영 이관 시 백엔드 API 연동이 용이하도록 계층 분리.

## 3. 마크다운 네이티브 법령 지식그래프(Markdown-native LKG) 모델링

전용 그래프 DB 도입 전 단계부터 즉시 운영할 수 있도록, **기관별 디렉토리 계층 구조**와 **조문별 마크다운 파일** 내의 **YAML Frontmatter + Wiki-Link(`[[...]]`)**를 결합하여 파일 시스템 기반 지식그래프를 구현합니다.

```
       ┌────────────────────────────────────────────────────────┐
       │   /statutes/국가법령/개인정보보호법/제15조.md              │
       │   - status: active / version: 2024-03-15               │
       └───────────────────────────┬────────────────────────────┘
                                   │ [[DELEGATES_TO]]
                                   ▼
       ┌────────────────────────────────────────────────────────┐
       │   /agencies/기관A/정보보안지침/제05조_데이터보호.md       │
       │   - parent: [[/statutes/국가법령/개인정보보호법#제15조]] │
       └─────┬─────────────────────┬────────────────────────────┘
             │                     │ [[HAS_PART]]
  [[CITES]]  │                     ▼
             │       ┌──────────────────────────────────────────┐
             │       │ /agencies/기관A/정보보안지침/별지제1호.md    │
             │       │ - form_type: input_form (LLaVA 복원 서식)  │
             │       └──────────────────────────────────────────┘
             ▼
┌────────────────────────────────────────────────────────┐
│ /agencies/기관A/정보보안지침/제12조_벌칙.md             │
└────────────────────────────────────────────────────────┘
```

### 3.1 디렉토리 및 파일 계층 구조 설계
```
legal-knowledge-vault/
├── statutes/                           # 국가 상위 법령 (법률, 시행령, 시행규칙)
│   └── 개인정보보호법/
│       ├── meta.yaml                   # 법령 기본 정보 및 개정 이력 메타데이터
│       ├── 제01조_목적.md
│       └── 제15조_개인정보의수집이용.md
├── agencies/                           # 기관별 내부 규정 체계
│   └── 한국행정연구원/                  # 특정 공공기관 디렉토리
│       ├── 정관/
│       └── 지침/
│           └── 공공데이터제공지침/
│               ├── meta.yaml           # 제·개정 히스토리 (Git 태그와 연동)
│               ├── 제01조_목적.md
│               ├── 제07조_데이터반출.md
│               └── 별표_서식/
│                   └── 별지제2호_데이터반출신청서.md
└── graph-index.json                    # 마크다운 파서(Lev)가 생성한 실시간 캐시 그래프
```

### 3.2 조문별 마크다운(`.md`) 파일 스펙 (스키마 정의)
개별 조문 마크다운 파일은 YAML Frontmatter로 그래프 노드/엣지 속성을 선언하고, 본문 텍스트 내에서 조문 간 참조를 위키링크(`[[경로#조문]]`)로 연결합니다.

```markdown
---
id: "KIPA-RULE-DAT-007"
agency: "한국행정연구원"
rule_name: "공공데이터제공지침"
article_no: 7
title: "데이터의 반출 허가"
version: "1.2.0"
last_amended: "2024-01-10"
delegated_by:
  - "[[/statutes/개인정보보호법#제15조]]"
  - "[[/statutes/공공데이터의제공및이용활성화에관한법률#제12조]]"
cites:
  - "[[/agencies/한국행정연구원/지침/보안업무지침#제20조]]"
uses_form:
  - "[[./별표_서식/별지제2호_데이터반출신청서.md]]"
defines_terms:
  - "연구데이터"
---

# 제7조 (데이터의 반출 허가)
① 연구자는 취급 중인 연구데이터를 기관 외부로 반출하고자 하는 경우 [[./별표_서식/별지제2호_데이터반출신청서.md|별지 제2호 서식]]을 작성하여 부서장의 승인을 받아야 한다.
② 제1항에 따른 데이터 중 개인정보가 포함된 경우에는 [[/statutes/개인정보보호법#제15조]] 및 [[/agencies/한국행정연구원/지침/보안업무지침#제20조]]에 따른 비식별 조치를 완료하여야 한다.
```

### 3.3 GitOps 기반의 지속적 변경(Delta) 관리 체계
규정의 제·개정 작업은 Git 저장소의 브랜치(Branch) 생성 및 풀 리퀘스트(PR) 워크플로우와 1:1로 매핑됩니다.

```
[ 상위법 개정 발생 or 개정안 발의 ]
                 │
                 ▼
[ Git Branch 생성 : feature/amend-rule-data-2026 ]
                 │
                 ▼
[ 마크다운 조문 수정 및 Diff 발생 ]
                 │
                 ▼
[ Lev Markdown Link Parser 작동 ]
  • Git Diff 분석: 수정·삭제된 조문 ID 추출
  • Backlink Index 조회: 해당 조문을 참조하던 하위 지침 전수 식별
  • 충돌 및 파급 보고서(Impact PR Report) 자동 코멘트
                 │
                 ▼
[ 검증 에이전트 승인 후 Main 브랜치 병합 (공포 및 시행) ]
```

1. **지속적 변경 감지(Living Graph)**: 상위 법령 마크다운 파일이 업데이트되면, Git Hook 또는 CI/CD 파이프라인이 즉시 작동하여 해당 파일의 경로를 참조하고 있는 모든 하위 마크다운 파일 목록을 역링크로 조회합니다.
2. **Re-numbering 감지**: 조문이 신설되거나 삭제되어 `제7조`가 `제8조`로 변경될 때, Git Diff에서 이전 번호(`제7조`)를 가리키던 모든 `.md` 파일 내의 `[[...#제7조]]` 링크를 일괄 교정 후보로 제시합니다.
3. **완전한 감사 추적(Audit Trail)**: 특정 시점(`git checkout v1.0.0`)의 커밋으로 이동하면 그 시점의 전체 규정 체계와 관계망이 그대로 복원되어, 과거 시점의 법령 정합성 검증이 언제든 가능합니다.

## 4. MCP(Model Context Protocol) 기반 시스템 아키텍처

마크다운 파일 기반의 지식그래프와 GitOps 파이프라인, 그리고 멀티모달 Vision 도구를 표준화된 **MCP 서버 클러스터**로 추상화합니다.

```
┌────────────────────────────────────────────────────────────────────────┐
│                          User Interface (Web)                          │
│   규정 제·개정 절차 위저드 / 실시간 조문 에디터 / 신구대비표 / 인터랙티브 그래프│
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ JSON-RPC (HTTP / WebSocket)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│            RuleCraft Orchestration Engine (Multi-Agent Host)           │
│   (Process Agent ↔ Research Agent ↔ Drafting Agent ↔ Verify Agent)     │
└───────┬───────────────────┬────────────────────┬───────────────────────┘
        │ stdio / SSE       │ stdio / SSE        │ stdio / SSE
        ▼                   ▼                    ▼
┌─────────────────┐ ┌─────────────────┐  ┌──────────────────────────────┐
│  Markdown Graph │ │  DocVision MCP  │  │  National Law & Diff MCP     │
```

## 5. 지능형 멀티 에이전트 분업 워크플로우

마크다운 지식그래프를 중심으로 특화된 5개 전문 에이전트가 협업하여 변경을 감지하고 문서를 패키징합니다.

```
[1. 워크플로우 총괄 에이전트] ──▶ 행정 절차 안내 & 단계별 태스크 발행
           │
           ├───────────────┬────────────────────────────┐
           ▼               ▼                            ▼
[2. 마크다운 LKG 조사 에이전트] [3. 비전 서식 분석 에이전트] [4. 조문 입안 에이전트]
  • 상하위 관계/역링크 탐색      • LLaVA 별표 서식 복원       • 법령 표준 문안 작성
  • Git Diff 영향도 역추적      • 서식 마크다운화            • YAML Frontmatter 생성
           │               │                            │
           └───────────────┼────────────────────────────┘
                           ▼
              [5. 법제 정합성 검증 에이전트]
                • Backlink 인용 유효성 전수 검사
                • Re-numbering 충돌 검사
                • 부칙 / 3단 신구대비표 생성
                           │ (통과 시)
                           ▼
                    [최종 공문서 패키지]
```

### ① 워크플로우 총괄 에이전트 (Administrative Workflow Orchestrator)
* **역할**: 사용자의 입력(제정/일부개정/전면개정) 목적을 분석하여 공공기관 행정 절차 체크리스트를 자동 수립.
* **산출물**: 5단계 행정 타임라인(입안 → 부서사전협의 → 입법예고 → 법제/규제심사 → 공포) 및 단계별 필수 구비 서류 가이드.

### ② 마크다운 LKG 조사 에이전트 (Markdown Knowledge Research Agent)
* **역할**: `Markdown Graph MCP`를 통해 수정하려는 조문의 Frontmatter와 Wiki-Link를 분석하여 상위법령 위임 한계와 관련 타 규정 관계망을 병렬 탐색.
* **핵심 기능**: "상위법 위임 범위 일탈 여부" 사전 진단 및 역링크(`Backlinks`)를 조회해 이 규정을 참조하고 있는 다른 지침과 서식 목록 도출.

### ③ 비전 서식 분석 에이전트 (DocVision LLaVA Agent)
* **역할**: 공공기관 규정 부록의 대다수를 차지하는 스캔된 별표·별지 서식, 서식 내 복잡한 표를 처리.
* **핵심 기능**: LLaVA를 통해 표의 병합 셀, 체크박스, 서명란을 정확한 Markdown Table 구조로 디지털 복원하여 별도 `.md` 서식 파일로 저장.

### ④ 조문 입안 에이전트 (Statutory Drafting Agent)
* **역할**: 법제처 『알기 쉬운 법령 정비 기준』에 맞추어 마크다운 조문 초안 및 YAML Frontmatter 메타데이터 자동 작성.
* **표준 문안 강제**: "~하여야 한다(의무)", "~할 수 있다(재량)", "~에 한한다(한정)" 등 규정 문체 엄격화.

### ⑤ 법제 정합성 검증 에이전트 (Zero-Defect Verification Agent)
* **역할**: 생성된 마크다운 조문의 링크, 조문 번호, 용어 일관성을 Git Diff 기반으로 전수 교차 검증.
* **핵심 기능**:
  1. **인용 유효성 검증**: 마크다운 파일 내 `[[...]]` 링크가 실제로 존재하는 파일 및 조문 앵커인지 확인.
  2. **Re-numbering 파급효과 계산**: 조문 번호 변경에 따른 타 마크다운 파일의 위키링크 자동 업데이트 스크립트 작성.
  3. **3단 신구조문대비표 자동 렌더링**: 개정 전/후 텍스트의 Token/Sentence 레벨 Diff를 분석하여 사유가 포함된 대비표 자동 생성.

## 6. 시연 시나리오 및 예선/결선 평가 대비

### 6.1 시연 시나리오: 『공공데이터 제공 및 AI 활용 내부 지침』 일부개정
1. **[마크다운 지식그래프 초기화]**:
   * 기관 규정집이 `/agencies/한국행정연구원/.../*.md` 형태로 적재되어 있으며, 상위법령 `/statutes/개인정보보호법/제15조.md`와 위키링크로 연결되어 있음.
2. **[상위법 개정 감지 및 Diff 입력]**:
   * 상위법인 「개인정보보호법」 제15조 마크다운 파일에 "인공지능 모델 학습용 데이터 수집·이용 요건"이 신설되는 커밋(Diff) 발생.
3. **[역링크(Backlink) 파급효과 추적]**:
   * `Markdown Graph MCP`가 상위법 제15조를 참조하던 `/한국행정연구원/공공데이터제공지침/제07조_데이터반출.md` 및 `별지제2호_데이터반출신청서.md`를 즉시 영향 대상(Impacted Nodes)으로 검출.
4. **[LLaVA 서식 정비 및 조문 드래프팅]**:
   * LLaVA가 스캔 이미지였던 별지 제2호 서식을 읽어 "AI 모델 학습 목적 반출" 체크박스를 추가한 마크다운 서식으로 개정.
   * 입안 에이전트가 `제7조의2(인공지능 학습데이터의 안전성 확보)` 조문 마크다운 파일을 신설.
5. **[Re-numbering 충돌 검사 & 패키징]**:
   * 검증 에이전트가 기존 제8조~제12조 번호 밀림에 따른 내부 지침 내 위키링크(`cites`) 깨짐을 감지하여 자동 치환.
   * 최종적으로 **① 개정 조문 마크다운 파일**, **② 3단 신구조문대비표**, **③ 제·개정이유서 및 부칙**, **④ 별지 서식 개정안**, **⑤ Git Diff 기반 영향도 분석 보고서**를 원스톱 출력.

### 6.2 심사위원 평가 포인트 요약
* **활용성 (40점)**:
  * 실무자가 겪는 가장 큰 고통인 "상위법 바뀌었을 때 우리 기관 규정 어디를 고쳐야 하는지"를 마크다운 역링크 그래프로 1초 만에 시각화.
  * 조문 초안부터 3단 대비표, 서식 개정안까지 완벽한 공문서 패키지 원클릭 제공.
* **완성도 (30점)**:
  * GitOps Diff 엔진과 마크다운 링커를 통해 조문 이동(Re-numbering) 및 허위 인용을 0%로 완벽 차단.
  * 멀티 에이전트 교차 검증을 통해 신뢰할 수 있는 법제 문안 보장.
* **확산 용이성 (30점)**:
  * **전용 Graph DB나 벤더 소프트웨어 없이, 오픈소스 마크다운 파일과 Git만으로 작동**하므로 모든 공공기관 폐쇄망 환경에 즉시 복제·이식 가능.
  * MCP 표준 인터페이스를 통해 향후 공공 전자결재 시스템 및 sLLM 인프라로 무중단 이관 지원.
