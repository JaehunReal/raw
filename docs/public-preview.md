# Vercel에서 공개 예제 보기

백엔드가 준비되기 전에도 현재 구현을 볼 수 있도록 **공개 읽기 전용 시연**을 별도로 빌드합니다. 공개 주소는 **[https://raw-ecru.vercel.app](https://raw-ecru.vercel.app)**입니다. 기존 Vercel `raw` 프로젝트가 GitHub `JaehunReal/raw`의 `main`에 연결되어 자동 배포합니다. 2026-10-01 실제 배포의 `READY` 상태와 익명 접근 HTTP 200을 확인했습니다.

## 지금 보여주는 내용

저장소에 있는 합성 규정 예제 12개와 관계 31개를 검색하고 원문을 읽습니다. 관계 탐색과 영향 후보 조회는 브라우저 안에서 동작합니다. 문서 패키지는 같은 합성 예제에서 생성한 7개 검토 문서를 읽을 수 있습니다. 편집 저장·새 패키지 생성·공식 수집·실시간 MCP 실행은 제공하지 않습니다.

공식 원문은 0건입니다. 2026-10-01 설정 적용 후 법령 목록 표본은 조회했지만 전문 HTTP 403과 행정규칙·자치법규 목록 HTTP 502로 연결이 미완료인 상태를 표시합니다. MCP 도구 4개와 관계 조회 3개 노드는 [기록된 검증 결과](api-connection-evidence.json)로 보여줍니다. 이 페이지에서 실제 MCP 프로세스를 실행했다는 뜻은 아닙니다.

## Vercel 계정에서 연결

1. [GitHub 저장소를 Vercel로 가져오기](https://vercel.com/new/import?s=https%3A%2F%2Fgithub.com%2FJaehunReal%2Fraw)를 열어 Vercel에 로그인합니다.
2. GitHub 연결에 필요한 저장소 접근을 허용하고 `JaehunReal/raw`를 선택합니다. 기존 저장소를 Import하며 새 GitHub 저장소를 만들 필요가 없습니다.
3. Root Directory를 `.`으로 유지합니다. 프레임워크는 `Other`이며 저장소의 `vercel.json`이 설치·빌드·출력 경로를 정합니다. 별도의 API 키나 환경 변수는 공개 시연에 필요하지 않습니다.
4. **Deploy**를 누릅니다. 빌드가 끝나면 Vercel이 실제 발급한 주소에서 공개 배너, 규정 목록, 관계 그래프와 모바일 화면을 확인합니다.

Vercel 웹에서 직접 연결하면 `VERCEL_TOKEN`이 필요하지 않습니다. 토큰을 이용한 자동 배포를 선택하면 비공개 환경 설정에 등록하고 Vercel API 접근을 허용해야 합니다. 토큰을 채팅이나 GitHub에 올리지 않습니다.

## 빌드와 운영 화면 전환

Vercel의 기본 빌드는 `VITE_PUBLIC_PREVIEW=true`로 정적 시연 화면을 표시합니다. Node.js 24, 루트 설치 명령과 `frontend/dist` 출력 설정은 저장소에 포함됩니다. API 함수는 계속 운영 인증을 요구하며, 시연 화면은 `/api`를 호출하지 않습니다.

로컬에서 같은 시연 빌드를 확인할 수 있습니다.

```bash
VITE_PUBLIC_PREVIEW=true VITE_REQUIRE_LOGIN=true npm run build --prefix frontend
```

실제 HTTPS 백엔드와 운영 인증을 준비한 뒤 Vercel 환경 변수 `VITE_PUBLIC_PREVIEW=false`를 설정하고 재배포합니다. 이때는 [운영 연결 설정](deployment.md)의 서버 주소·연결 토큰·로그인 비밀번호가 필요하며 기존 로그인 화면과 API 경로를 사용합니다.

공개 데이터는 Git에 있는 합성 시연 폴더에서 생성한 고정 예제입니다. 실제 기관 규정·개인 데이터·비공개 설정이나 수집 원문을 공개 시연에 넣지 않습니다. 운영 백엔드 구축은 계속 대기 상태입니다.

개발 중 공개 예제를 갱신할 때는 저장소 루트에서 `uv run --project backend --frozen python scripts/build-public-preview.py`를 실행하고 생성된 JSON과 소스 변경을 함께 저장합니다. 이 명령은 `.env`를 불러오지 않으며, 명시적인 시연 표시가 없는 문서와 인증값 필드를 거부합니다. Vercel은 Git에 포함된 JSON으로 빌드하므로 Python 백엔드를 실행하지 않습니다.

## 확인한 동작

저장소의 실제 Vercel 빌드 명령과 운영 로그인 빌드가 통과했습니다. 실제 Chromium으로 7개 메뉴, 문서 원본 12개, 관계 31개, 패키지 문서 7개의 내용을 비교했습니다. 390px 모바일 가로 넘침과 실행 오류는 0이며, 공개 화면은 API와 외부 서버에 요청하지 않았습니다. 운영 로그인 화면 선택도 별도의 정적 테스트 서버에서 확인했습니다.

[빌드·브라우저 검증 기록](public-preview-evidence.json)에 로컬 빌드와 실제 공개 주소의 검증 범위를 구분해 기록합니다. Vercel 계정 인증과 GitHub 연동, 공개 시연 배포를 확인했으며 운영 백엔드는 계속 대기 상태입니다.

실제 공개 주소에서도 7개 메뉴, 문서 12개, 관계 31개, 패키지 7개가 저장소와 일치했고 데스크톱·390px 모바일 검증을 통과했습니다. 클라우드 Chromium의 세션 프록시 인증서 신뢰 오류 때문에 실제 원격 HTML과 자산을 TLS 검증을 유지한 Python HTTPS 요청으로 가져와 브라우저에 전달했습니다. 로컬 파일로 대체하거나 TLS 검증을 해제하지 않았습니다. 이는 이 전송 경로에서의 원격 내용·화면 검증이며 Chromium 자체의 인증서 신뢰 검증은 아닙니다. 백엔드가 필요한 익명 요청은 HTTP 503으로 연결 대기 상태를 반환합니다.
