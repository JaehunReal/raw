# Render 백엔드 배포 설정

Vercel의 웹 화면과 별도로, Python API는 항상 실행되는 Render Docker Web Service에서 운영합니다. SQLite·공식 원문·작업 체크포인트·편집 규정·패키지는 `/var/data` 영구 디스크에 보관합니다. 요청마다 시작하는 MCP 자식 프로세스도 같은 Python 가상환경과 저장 경로를 사용합니다.

`render.yaml`은 **유료 Starter 서비스 1개와 유료 20GB 영구 디스크**를 생성하는 배포안입니다. 무료 서비스는 이 구성의 항상 실행되는 프로세스와 영구 디스크 요구를 충족하지 못합니다. Blueprint를 실제 생성하면 서비스와 디스크 요금이 발생하며, 금액은 생성 당시 Render의 요금표에서 확인해야 합니다. 이 파일 작성만으로 서비스를 생성하거나 비용을 결제하지 않습니다.

| 설정 | 값 / 용도 |
| --- | --- |
| 리전 | Singapore |
| 서비스 프로세스 | Uvicorn worker 1개; 자동 수평 확장 없음 |
| Health check | `/api/health` |
| 로컬 규정 | `/var/data/vault` |
| 공식 법령 SQLite·원본·체크포인트 | `/var/data/national-law` |
| 생성 문서 패키지 | `/var/data/packages` |
| 백엔드 인증 | Render가 생성하는 `RULECRAFT_API_TOKEN` |
| 공식 법령 계정 | 선택적 `RULECRAFT_LAW_OC`; 기본 빈 값 |

Dockerfile은 Python 3.12.14와 uv 0.12.19를 사용하고 `backend/uv.lock`으로 `uv sync --frozen --no-dev --no-install-project`를 실행합니다. 프로젝트 원본은 `PYTHONPATH`로 읽어 별도 빌드 도구를 잠금파일 밖에서 내려받지 않습니다. `.dockerignore`는 기존 데이터·가상환경·환경 파일·Git 인증 정보가 이미지에 들어가지 않도록 제외합니다. 배포 빌드에 쓰는 이미지 태그 자체는 공급자가 갱신할 수 있으므로 이미지 단위의 바이트 동일성까지 보장하지 않습니다.

시작 프로그램은 인증 토큰이 없으면 API 초기화 전에 종료합니다. 첫 시작에 `/var/data/vault`가 없을 때만 시연 규정을 복사하고, 기존 규정이나 사용자가 비워 둔 규정 폴더를 덮어쓰지 않습니다. 데이터 폴더를 준비한 뒤 UID/GID 10001로 권한을 낮추어 서버를 시작합니다. 기존 데이터를 복원할 때 파일 소유권도 이 UID/GID에 맞춰야 합니다. 시연 원문과 공식 수집 자료는 별도 폴더를 유지합니다.

배포 시 Render에서 생성된 토큰을 Vercel의 서버 전용 환경 변수에 같은 값으로 등록합니다. 토큰을 `VITE_` 변수, 브라우저 코드, 저장소 또는 로그에 넣지 마세요. Vercel 프록시도 사용자 접근을 통제해야 하며, 백엔드 토큰을 자동으로 붙이는 공개 프록시는 사용자 인증을 대신하지 않습니다. `RULECRAFT_LAW_OC`는 Render의 환경 설정에서 별도로 공급하며, 값이 없으면 웹 앱은 실행되지만 공식 법령 수집은 사용할 수 없습니다. API 계정과 해당 Render 환경의 법령 API 접속도 실제 요청으로 확인해야 합니다.

Starter와 20GB는 초기 실행안입니다. 전국 단위 수집량, 원문 버전 누적, SQLite 크기 및 실제 메모리 사용량을 확인하고 디스크·서비스를 증설해야 합니다. 버전은 원문을 보존하므로 공간 사용량이 계속 늘 수 있습니다. 영구 디스크는 데이터 유지 장치이며 별도의 백업·복구 검증을 대신하지 않습니다. SQLite가 열려 있는 폴더를 단순 복사하기보다 SQLite backup 기능 또는 서비스를 정지한 일관된 백업을 사용합니다.

프로세스가 재시작되면 실행 중인 작업의 화면 상태는 사라지지만 수집 체크포인트와 원문은 유지됩니다. 새 수집 요청은 목록을 다시 확인하고 같은 공식 버전의 저장된 원문을 재사용합니다. 작업이 자동으로 재시작된다고 간주하지 마세요. 단일 디스크·단일 프로세스 구성은 수평 확장이나 무중단 데이터베이스 운영을 제공하지 않습니다. 공식 수집 및 MCP 요청을 Vercel 서버리스 함수 자체에서 실행하지 않습니다.

Git 실행 파일은 이미지에 포함됩니다. 이미지에는 `.git` 이력이 포함되지 않으므로 초기 시연 폴더의 Git 커밋 비교는 사용할 수 없습니다. 이력 비교가 필요하면 영구 규정 폴더에 관리 중인 저장소와 Git 이력을 별도로 복원해야 합니다. 제안 Markdown·Unified Diff 미리보기와 공식 법령의 저장 버전 비교는 별도로 동작합니다.

관리형 Codex 환경에서 이미지 검증을 실행하는 경우 세션의 프록시 설정을 유지하고 다음처럼 CA를 빌드에 임시 마운트합니다. 인증서 파일을 이미지에 복사하거나 TLS 검증을 끄지 않습니다.

```bash
docker build --secret id=proxy_ca,src=/etc/ssl/certs/ca-certificates.crt -t rulecraft-api:local .
```

일반 Render 빌드에는 세션 전용 프록시 CA가 필요하지 않습니다. 정상적인 공개 CA 검증을 그대로 사용합니다.

이번 클라우드 환경의 실제 이미지 빌드는 첫 Dockerfile 구문 이미지의 `registry-1.docker.io/v2/docker/dockerfile/manifests/1` 요청이 `Forbidden`으로 차단되어 중단했습니다. 따라서 여기서는 이미지 다운로드·컨테이너 기동을 검증하지 못했습니다. 초기 데이터 복사와 편집·빈 규정 폴더의 재시작 보존, 소유권 설정, 경로 이탈 거부는 임시 폴더에서 검증했습니다. 공개 Render 배포에서도 빌드 로그와 실제 서비스 상태를 확인해야 합니다.
